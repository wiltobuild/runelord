### Recorded result

**Very doable—moderate effort, with most of the existing game reusable.** After inspecting Runelord, it’s already better prepared for Android than I expected.

It uses **React, TypeScript, and PixiJS**, and already includes touch-specific styling, landscape handling, fullscreen controls, and mobile screen scaling.

I’d use **[Capacitor](https://capacitorjs.com/docs)** to package the existing game inside an Android app. That preserves the combat engine, artwork, and most of the interface while allowing Android-specific features.

My rough estimates for the current playable game:

| Target | Estimated effort |
|---|---|
| Installable Android prototype | 1–3 days |
| Comfortable, reliable phone version | 1–2 weeks |
| Polished release candidate | 2–4 weeks, excluding store review |

The main work would be:

- **Readability and touch controls:** the battle screen scales down from a 1672×941 layout, so cards and small buttons need real-phone testing.
- **Performance and download size:** the public assets total about **295 MB before packaging**. Animation memory, effects, and loading need profiling.
- **Android behavior:** handle Back, backgrounding, audio interruptions, fullscreen, and reliable save/resume.
- **Release packaging:** app icons, signing, and device testing.

**I’d start with a landscape Android prototype on your phone.** That will quickly reveal whether the remaining work is mostly polish or needs deeper performance changes. These estimates are based on code inspection; I haven’t run it on Android yet.
